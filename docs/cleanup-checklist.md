# B3-1 리소스 정리 — 서비스가 안 보이게 되는 것과 비용이 끝나는 것은 다르다

> **외부 접속 및 IAM 문제 해결 증빙 확보. AWS 콘솔에서 EC2 `Terminated`, EBS 볼륨 0건, 실습 Subnet 및 전용 Route Table 삭제를 확인했습니다. IGW/SG/VPC 및 IAM·키페어 삭제는 아직 미확인입니다.** 아래의 [ ]는 **실제 확인 후에만** [x]로 바꾸세요. AWS 서울 리전에서 이름이 `b3-1-`인 **이 실습에서 생성한 자원만** 삭제하고, 계정의 기존 프로젝트 자원은 건드리지 않습니다.

## 왜 'EC2 Stop'만 하면 안 되나?

EC2를 **Stop(중지)**하면 컴퓨터 작동은 멈추지만 EBS 볼륨 등은 남을 수 있습니다. 다른 사람이 URL로 접속할 수 없게 된 것과 **비용 발생 원인이 없어졌다**는 것은 다른 문제입니다. 미션은 리소스를 **종료/삭제하고 확인**하라고 요구하므로, 종료 전 증빙을 남기고 실제 자원을 확인해야 합니다.

## 실제 정리 진행 관측 (2026-10-26 KST)

- [x] AWS EC2 콘솔에서 `i-0fe03d78532fbbe17`에 대해 **'종료(삭제) 처리됨'** 성공 배너를 확인 (종료 요청 성공).
- [x] **인스턴스 종료 확인:** 인스턴스 필터를 해제한 서울 리전 EC2 목록에서 `b3-1-web` (`i-0fe03d78532fbbe17`) 상태 **`종료됨(Terminated)`** 확인.
- [x] **EBS 삭제 확인:** 서울 리전 EBS 볼륨 목록이 **0건**으로 표시됨. 루트 볼륨 `vol-0eb866e2e013ed6f3` (gp3, 8 GiB)가 목록에서 사라진 것을 확인.
- [x] **실습 Public Subnet 삭제 확인:** AWS VPC 콘솔에서 `subnet-078b1593e96abeeb0` 삭제 완료 배너 확인. 이후 서브넷 목록에 기본 VPC(`vpc-063331ec92f7b3dfb`) 소속 서브넷 4개만 남음.
- [x] **전용 Route Table 삭제 확인:** `b3-1-public-route` (`rtb-0476ec11e4a44b4af`)가 목록에서 사라졌고 서울 리전 테이블 개수가 3개에서 2개로 줄어듦. 기본(Main) 테이블은 직접 삭제하지 않음.
- [ ] 나머지 VPC/IGW/Security Group/키페어/IAM/Billing 정리는 아직 확인되지 않음.

**관측 범위:** 실제 AWS 콘솔 스크린샷에 표시된 상태만 기록합니다. 리소스 삭제 완료 증빙으로 과장하지 않습니다.

|---|---|---|---|

| 2 | 루트 EBS 8GiB 볼륨/미사용 볼륨 삭제 확인 | [x] | 서울 리전 EBS 볼륨 목록 0건, 기존 `vol-0eb866e2e013ed6f3` 사라짐, 2026-10-26 KST |
| 3 | `b3-1-public-subnet` 삭제 | [x] | `subnet-078b1593e96abeeb0`: 삭제 완료 배너 및 목록에서 사라짐, 2026-10-26 KST |

## 경로 B: CloudFormation을 사용했을 때

이 경로에서만 아래 명령을 사용합니다.

```bash
export AWS_PROFILE=b3-1
aws cloudformation delete-stack --region ap-northeast-2 --stack-name b3-1
aws cloudformation wait stack-delete-complete --region ap-northeast-2 --stack-name b3-1
```

- [ ] `b3-1` 스택이 삭제 완료됐는지 확인했다.
- [ ] 스택 삭제 중 오류가 나면 CloudFormation Events에서 실패 리소스를 확인하고 해결했다.
- [ ] EC2, EBS, SG, Subnet, Route Table, IGW, VPC가 **실제로 잔존하지 않는지** 확인했다.

CloudFormation은 템플릿으로 **관리한 자원만** 삭제를 시도합니다. 수동으로 만든 키페어·IAM 사용자는 **스택 밖의 자원**입니다.

### 평가할 때 스스로 설명할 질문

"웹페이지가 안 보이는데 왜 과금이 남을 수 있는가?" → **EC2 중지, EBS 존재, 퍼블릭 IP 할당 등은 서로 다른 상태**이고, 과금 항목도 다르기 때문입니다. 이 구분이 클라우드 운영의 기본입니다.
