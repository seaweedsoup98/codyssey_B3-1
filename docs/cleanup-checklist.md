# B3-1 리소스 정리 — 서비스가 안 보이게 되는 것과 비용이 끝나는 것은 다르다

> **현재 AWS에서 종료/삭제를 수행한 기록이 없습니다.** 아래의 [ ]는 **실제 확인 후에만** [x]로 바꾸세요. AWS 서울 리전에서 이름이 `b3-1-`인 **이 실습에서 생성한 자원만** 삭제하고, 계정의 기존 프로젝트 자원은 건드리지 않습니다.

## 왜 'EC2 Stop'만 하면 안 되나?

EC2를 **Stop(중지)**하면 컴퓨터 작동은 멈추지만 EBS 볼륨 등은 남을 수 있습니다. 다른 사람이 URL로 접속할 수 없게 된 것과 **비용 발생 원인이 없어졌다**는 것은 다른 문제입니다. 미션은 리소스를 **종료/삭제하고 확인**하라고 요구하므로, 종료 전 증빙을 남기고 실제 자원을 확인해야 합니다.

## 시작 전 두 가지 확인

- [ ] **실습 당시** `GET http://<PUBLIC_IP>/health` 200/OK 스크린샷을 `docs/screenshots/external-health.png`에 저장했고 README에 실제 URL 및 시각을 적었다.
- [ ] `docs/troubleshooting.md`에 실제 오류 관찰 → 로그/검증 → 조치 → 결과를 1건 이상 기록했다.

**먼저 답해야 할 질문:** 어떤 방법으로 만들었나요?

- **경로 A:** AWS 콘솔에서 VPC, Subnet, EC2를 각각 직접 만들었음 → 아래 **수동 삭제**.
- **경로 B:** `template.yaml`의 CloudFormation 스택 `b3-1`으로 만들었음 → 아래 **스택 삭제**.
- 둘 다 했다면 자원이 **서로 별개로 존재할 수 있습니다**. 각각 확인하세요.

## 경로 A: AWS 콘솔로 만들었을 때

리소스는 연결되어 있으므로 무작정 VPC부터 삭제하려고 하면 "사용 중" 오류가 날 수 있습니다. **컴퓨터 → 컴퓨터가 쓰는 자원 → 네트워크** 순으로 정리합니다.

| 순서 | 확인 항목 | 완료 | 확인한 ID·시각·상태 |
|---|---|---|---|
| 1 | `b3-1-web` EC2를 **Terminate**하고 Terminated 확인 | [ ] | 미확인 |
| 2 | 루트 EBS 8GiB 볼륨/미사용 볼륨 삭제 확인 | [ ] | 미확인 |
| 3 | `b3-1-public-subnet` 삭제 | [ ] | 미확인 |
| 4 | `b3-1-public-route` 연결 해제 및 삭제 | [ ] | 미확인 |
| 5 | `b3-1-igw` VPC Detach 후 삭제 | [ ] | 미확인 |
| 6 | `b3-1-web-sg` 삭제 (기본 SG 제외) | [ ] | 미확인 |
| 7 | `b3-1-vpc` 삭제 | [ ] | 미확인 |

**중요한 함정:** Terminate를 눌렀더라도 네트워크 인터페이스/볼륨 정리가 완료되기 전에 SG나 Subnet 삭제를 시도하면 오류가 날 수 있습니다. **정리 진행을 기다린 다음** 해당 자원만 재확인하세요.

## 경로 B: CloudFormation을 사용했을 때

이 경로에서만 아래 명령을 사용합니다.

```bash
export AWS_PROFILE=b3-1
aws cloudformation delete-stack --region ap-northeast-2 --stack-name b3-1
aws cloudformation wait stack-delete-complete --region ap-northeast-2 --stack-name b3-1
```

- [ ] `b3-1` 스택이 삭제 완료됐는지 확인했다.
- [ ] 스택 삭제 중 오류가 나면 CloudFormation Events에서 실패 리소스를 확인하고 해결했다.
- [ ] EC2, EBS, SG, Subnet, Route Table, IGW, VPC가 **실제로 잔존하지 않는지** 확인했다.

CloudFormation은 템플릿으로 **관리한 자원만** 삭제를 시도합니다. 수동으로 만든 키페어·IAM 사용자는 **스택 밖의 자원**입니다.

| 항목 | 완료 | 확인한 근거·시각 |
|---|---|---|

| NAT Gateway/Load Balancer/RDS를 따로 만들지 않았거나, 있다면 삭제 확인 | [ ] | 미확인 |
| EC2 인스턴스와 불필요한 EBS가 남지 않음 | [ ] | 미확인 |
| 실습 전용 AWS 키페어 `b3-1` 정리 | [ ] | 미확인 |
| 더 사용하지 않는 로컬 `.pem` 삭제(개인 키 내용 공개 금지) | [ ] | 미확인 |
| 실습 전용 IAM 사용자/정책은 **관리용 IAM 사용자로** 정리 (다른 용도로 쓰면 유지 여부 검토) | [ ] | 미확인 |

**요금은 실시간으로 0원이 표시되지 않을 수 있습니다.** Billing 정보에는 지연이 있을 수 있으므로 리소스 목록의 실제 삭제 상태와 비용 대시보드를 구분해 확인합니다.

### 평가할 때 스스로 설명할 질문

"웹페이지가 안 보이는데 왜 과금이 남을 수 있는가?" → **EC2 중지, EBS 존재, 퍼블릭 IP 할당 등은 서로 다른 상태**이고, 과금 항목도 다르기 때문입니다. 이 구분이 클라우드 운영의 기본입니다.
